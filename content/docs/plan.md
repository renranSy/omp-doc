# 计划模式

## 什么 `/plan` 确实

`/plan` 将编辑器替换为计划审查界面，并将下一个提示路由到 `plan`\-侧通道Turn的榜样。规划器只能进行只读工作：它只能创建和编辑其规划文件（`local://<slug>-plan.md`），因此在您批准之前，没有任何其他内容会触及您的代码。

通过键入从编辑器切换它 `/plan`，通过按 Alt+Shift+P，或者通过内联传递初始目标：

```text
/plan refactor src/importer.ts to stream rows instead of buffering
```

## 计划角色模型

计划模式 针对一个单独的角色运行，因此您可以在那里固定一个更强大的推理者，而无需每回合都付费。覆盖每次运行 `--plan <model-id>`，每个Shell `PI_PLAN_MODEL`，或坚持不懈地 `modelRoles.plan` 在 [`config.yml`](/docs/settings)。 registry 和可用的模型 ID 位于 [模型](/docs/custom-models) 页。

## 循环

1.  **陈述目标。** 计划模式横幅出现在编辑器的顶部；提示您输入下一条路线到规划器。
2.  **迭代。** 规划者起草；你像正常Turn一样回复更正。只读工具仍然可用，因此它可以 grep 存储库、读取 PR 并在修改之前检查假设。
3.  **批准。** 当您告诉规划师您感到满意时，它会打电话给您 `resolve` 与 `action: "apply"` 然后出现批准选择器。

## 退出时会发生什么

批准屏幕提供了三种形状，用于将计划交给执行者。它们的不同之处在于执行者所认为的“迄今为止的对话”。

**批准并执行**

计划模式讨论是 *清除的* 从上下文来看；执行从新的记录开始 计划作为开场白。当计划很长并且来回不重要时使用。

**批准并保留上下文**

完整的规划历史记录保留在记录中。当迭代通知您想要的细微差别时使用 执行者要记住。

**批准并压缩上下文**

规划讨论被总结为一个条目；在同一会话中继续执行。中 地面。

Escape 批准屏幕上的取消：您停留在计划模式迭代中并且不执行任何操作。

批准计划会根据计划标题自动命名会话（分隔符标准化、大写）。您自己重命名的会话将被保留。

## 快捷键

| 钥匙 | 行动 |
| --- | --- |
| Alt+Shift+P | 切换 计划模式（别名为 `/plan`) |
| Escape 在批准屏幕上 | 取消；返回计划模式迭代而不执行 |

计划模式 中的其余编辑器和导航器快捷键保持不变；看到 [快捷键](/docs/keybindings).

## 何时伸手去拿它

计划模式 在涉及多个文件的更改、具有不明显顺序的重构以及规划者在实施之前应证明其合理性的设计上得到了回报。对于单文件编辑和琐碎更改，请跳过它；计划者往返花费了你无法收回的Token。

自然搭配 [分支](/docs/sessions)：规划一个侧分支，如果设计没有落地就扔掉该分支，继续在父级上迭代。
